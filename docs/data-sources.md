# 数据来源说明

## 当前数据源分层

当前项目的核心计算源仍是 `Twelve Data API`。所有长期历史、图表和区间指标都从本地 SQLite 的日线数据计算，不直接采用第三方返回的收益结论。

首页头部有一层单独的展示数据：

- `Twelve Data quote`：早晨快照、手动快照、纽约时段 ETF 轻量实时价
- `FMP quote-short`：首页头部真实指数点位优先源
- `Stooq daily csv`：首页头部真实指数点位备用源

FMP / Stooq 只服务“真实指数点位”展示，不写入长期日线，也不参与收益、年化、回撤计算。

原因：

- 个人项目接入成本低
- 免费额度足够当前场景
- 接口结构清晰，便于 AI 和人类共同维护
- 适合盘后日线场景

## 当前核心调用方式

接口：

- `time_series`：正式日线
- `quote`：快照与轻量实时价

参数策略：

- 首页核心标的：`SPY` / `QQQ`
- 汇率补充页：`USD/CNY` / `USD/JPY` / `USD/INR` / `USD/EUR`
- BTC 补充页：`BTC/USD`
- `interval=1day`
- 初始化时按可行范围回补长期历史
- 日常同步只拉最近一小段增量区间

## 为什么使用 ETF 而不是指数本体

当前不是做机构级指数授权系统，而是做个人使用面板。

因此优先级是：

1. 稳定拿到可用数据
2. 低授权复杂度
3. 能支撑本地计算日 / 周 / 月涨跌

在这个前提下：

- `SPY` 足以代表标普 500
- `QQQ` 足以代表纳指 100

## 免费额度评估

当前正式日线同步只需要少量请求：

- `SPY`
- `QQQ`
- 汇率页面的固定观察货币对
- `BTC/USD`

初始化补历史时，请求会更多一些，但总体仍然处于可控范围。手动快照与首页轻量实时价走 `quote`，按页面组做节流与缓存，避免无意义的高频请求。

## 未来切换空间

如果后续确实需要切回指数本体，可以按这个顺序升级：

1. 保留当前页面和本地计算逻辑
2. 更换同步脚本的数据来源
3. 视情况调整 symbol 与市场映射

这样可以把数据源切换控制在较小范围内，而不是重做整个项目。
